# Update record — 2026-09-22

This update consolidates duplicate utilities and magnetic-moment data, improves
large-file analysis performance, and archives the legacy Gaussian energy utility.

## Repository cleanup

- Removed the root `mag_value_database_summary.csv`. All 22 element records,
  including magnetic moments, atom counts, and source CSV counts, are preserved
  in `brain/incar.py` as `mag_value_database` and `mag_value_database_counts`.
- Removed the duplicate magnetic-moment database from `brain/data.py`.
  Hand-tuned defaults remain available there for elements absent from the database.
- Updated `actions_py/update_incar.py` to refresh the data in `brain/incar.py`
  without recreating the root summary CSV. Per-calculation `Magnetization.csv`
  output remains supported. Updated the action registry accordingly.
- Removed the empty root `mol2poscar.py`. The implementation remains in
  `actions_py/mol2poscar.py`.
- Kept `actions_py/sort_atoms.py` and removed `actions_py/sort_ele.py`.
  The retained script supports custom element ordering, global z sorting,
  z sorting within element groups, fixing atoms below a z cutoff, and
  Cartesian output. Example:

  ```bash
  python actions_py/sort_atoms.py POSCAR Cu C H O
  ```

## Job automation retained

Kept `actions_bash/autocheck.sh` after reviewing its role. It monitors VASP
calculation folders through Slurm, checks convergence, and resubmits failed jobs.
It saves partial calculations before reruns when appropriate and moves completed
folders from a supplied job list into `job_done.txt`. Its default polling interval
is 30 minutes. The Python performance changes preserve its automation exit codes.

## Python performance improvements

Optimized 24 existing Python scripts and shared modules. Scripts without an
identified bottleneck were left unchanged.

### OUTCAR analysis

- Added shared reverse-reading and streaming helpers in `brain/outcar.py`.
  Final-value lookups read backwards in 64 KiB chunks and stop when they find
  the requested record, rather than loading and indexing the entire file.
- Applied targeted reads to final energies, Fermi levels, vacuum levels,
  magnetization tables, geometry blocks, and iteration information.
- Reduced convergence analysis from repeated full-file reads to a header read
  plus one streaming pass. Normal-finish information is collected in that pass.
- Streamed frequency records and imaginary-mode displacements. ZPE extraction
  now obtains real and imaginary frequencies in one pass and imports ASE only
  when temperature-dependent thermochemistry is requested.
- Updated thermochemistry, bandgap, NEB plotting, magnetization database,
  and job-checking callers to use the shared readers. Kill-marker checks read
  only the requested log tail.

Energy definitions remain explicit: `get_energy()` returns `energy(sigma->0)`;
`get_toten()` returns free-energy TOTEN. `get_GS_species.py` retains its TOTEN
fallback. Shared frequency parsing preserves repeated modes, while callers
retain their existing deduplication and cutoff policies.

### Other analysis and file handling

- `dcenter.py` loads its DOS table once and uses NumPy integration operations,
  preserving its existing range endpoints.
- MD coordinate extraction streams frames and reuses the cell transformation.
  Fixed the mismatch with the lattice helper's return value and reporting of
  the first detected bond-breaking step.
- XML-to-ML_AB conversion streams calculation elements instead of retaining
  the full XML tree and an intermediate list of every parsed step.
- Reduced extra OUTCAR loading during OUTCAR-to-ML_AB conversion, while
  retaining ASE for final-frame positions and forces.
- Magnetization selection reuses previously read structure symbols.
- Database aggregation streams atom records instead of collecting all rows
  into a list. Bader and POSCAR-header readers avoid unnecessary full-file reads.
- POTCAR concatenation copies data in chunks.

ASE remains in use for geometry and thermochemistry. `get_mag_ase.py` retains
its ASE reader for selecting arbitrary ionic frames. Analyses requiring every
step still scan the input, and APIs returning all configurations still retain
those requested results in memory.

## Gaussian utility archived

Moved `actions_py/get_energy.py` to `deprecated/get_energy.py`. This is the legacy
Gaussian-log utility and requires the `gpm` module; it is not a VASP energy
command. Updated `actions_py/USAGE.md` and `manual/py_usage.md` to reflect its
location and purpose. There is no `get_energies.py` in this checkout.
